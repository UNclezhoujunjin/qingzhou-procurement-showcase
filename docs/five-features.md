# 五项业务补齐说明

## 多商品采购

一张申请支持 1～100 项不同商品，每项数量 1～100000。提交时保存商品名称、SKU、单位、单价和供应商快照。审批通过后，采购人员按供应商自动拆成订单；同一申请同一供应商仅生成一张订单，重复下单返回原结果。

旧版单商品申请和订单会自动迁移为一条明细，原编号、申请人、审批结果、库存和流水保留。旧版单商品输入仍兼容，但不能同时使用新旧两种明细格式。

## 分批收货与采购退货

仓管或管理员在订单中填写本次数量，不处理的明细填 0。累计净收货不能超过采购数量。每次操作生成独立事件和库存流水，详情可查看操作人、时间、商品和说明。

采购退货必须关联订单明细并填写原因，数量不能超过净收货数量，现有库存也必须足够。退货后重新形成待补货数量，后续可以补收；累计收货可能包含补货次数，所以使用“累计收货 − 累计退货”计算净收货。库存不等同于净收货，因为其中物资可能已经被领用。

订单状态显示待收货、部分收货、已收齐或已退货待补货。一个申请拆成的所有订单收齐后，申请才显示完成。当前采购退货按补货处理，不包含退款、财务红冲或采购订单取消。

## 盘点与领用归还

盘点先捕获商品的账面数与库存版本，再填写实盘数；提交时如果期间库存变化，整单回滚，要求重新核对。盘盈盘亏生成调整流水，数量一致也保留盘点单，但不生成零数量流水。

领用归还必须选择原领用出库记录，累计归还不能超过原领用量；完整归还后从待归还列表移除。采购退货、领用归还与盘点调整使用不同业务类型，可在流水中区分。

## 个人中心与通知

个人中心维护姓名、邮箱、电话；部门和角色仍由管理员管理。修改密码需要正确的当前密码，新密码至少 8 字符且 UTF-8 不超过 72 字节。资料或密码改变后原登录失效，需重新登录。

站内通知涵盖新申请审批、审批结果、待下单、待收货、分批收货、采购退货及库存跌破安全线。通知仅本人可读，支持未读筛选、分页、单条已读和全部已读；页面每 30 秒更新未读数。当前未接入短信、邮件或企业聊天工具。

## 本机稳定运行与备份

见 [运行与恢复说明](operations.md)。默认改为构建后的页面与 Java API 单服务运行，包含守护重启、当前用户登录启动项、每日在线备份、校验、下载、离线恢复与恢复前副本。

当前仍为单组织、单仓库、单级审批。没有扩展到预算、付款、发票、复杂审批流、多租户或公网托管。
